# RSpec-Rails

RSpec is the most popular Ruby testing framework. Combined with Rails, it tests models, controllers, requests, and browser behavior with a readable DSL.

## Setup

```ruby
# Gemfile
group :development, :test do
  gem "rspec-rails"
  gem "factory_bot_rails"   # Fixtures replacement
  gem "faker"               # Fake data generator
end

group :test do
  gem "capybara"            # Browser simulation for system specs
  gem "selenium-webdriver"  # JavaScript driver
  gem "shoulda-matchers"    # One-liner matchers for common tests
end
```

```bash
bundle install
rails generate rspec:install
```

This creates:
- `spec/spec_helper.rb` — basic RSpec configuration
- `spec/rails_helper.rb` — Rails-specific configuration
- `.rspec` — command line defaults

## Model Specs (Unit Tests)

Test a single model in isolation. Located at `spec/models/model_name_spec.rb`.

```ruby
# spec/models/post_spec.rb
RSpec.describe Post, type: :model do
  describe "validations" do
    it "is valid with valid attributes" do
      post = Post.new(title: "Hello", body: "World", user: create(:user))
      expect(post).to be_valid
    end

    it "is invalid without a title" do
      post = Post.new(title: nil)
      expect(post).not_to be_valid
      expect(post.errors[:title]).to include("can't be blank")
    end

    it "is invalid with a short title" do
      post = Post.new(title: "Hi")
      expect(post).not_to be_valid
      expect(post.errors[:title]).to include("is too short")
    end
  end

  describe "scopes" do
    let!(:published_post) { create(:post, published: true) }
    let!(:draft_post) { create(:post, published: false) }

    it "returns only published posts" do
      expect(Post.published).to include(published_post)
      expect(Post.published).not_to include(draft_post)
    end
  end

  describe "associations" do
    it "belongs to a user" do
      association = described_class.reflect_on_association(:user)
      expect(association.macro).to eq(:belongs_to)
    end
  end
end
```

## Factory Bot (Test Data)

Instead of manually creating objects, define factories in `spec/factories/`:

```ruby
# spec/factories/posts.rb
FactoryBot.define do
  factory :post do
    title { "My Post" }
    body  { "Content of the post" }
    published { false }
    association :user
  end
end

# spec/factories/users.rb
FactoryBot.define do
  factory :user do
    name  { Faker::Name.name }
    email { Faker::Internet.email }
  end
end
```

In your tests:

```ruby
# Creates but does not save (build)
post = build(:post)

# Creates and saves (create)
post = create(:post)

# Override attributes
post = create(:post, title: "Custom Title")

# Build a post with a specific user
user = create(:user)
post = create(:post, user: user)
```

Enable Factory Bot methods globally in `spec/rails_helper.rb`:

```ruby
RSpec.configure do |config|
  config.include FactoryBot::Syntax::Methods
end
```

## Request Specs (Integration Tests)

Test a full request-response cycle through a controller. Located at `spec/requests/posts_spec.rb`.

```ruby
# spec/requests/posts_spec.rb
RSpec.describe "Posts", type: :request do
  let(:user) { create(:user) }
  let(:post) { create(:post, user: user) }

  describe "GET /posts" do
    it "returns a successful response" do
      get posts_path
      expect(response).to have_http_status(:success)
    end

    it "lists posts" do
      post  # Create the post
      get posts_path
      expect(response.body).to include(post.title)
    end
  end

  describe "GET /posts/:id" do
    it "returns the post" do
      get post_path(post)
      expect(response).to have_http_status(:success)
      expect(response.body).to include(post.title)
    end
  end

  describe "POST /posts" do
    let(:valid_params) do
      { post: { title: "New Post", body: "Content", user_id: user.id } }
    end

    it "creates a new post" do
      expect {
        post posts_path, params: valid_params
      }.to change(Post, :count).by(1)
    end

    it "redirects after creation" do
      post posts_path, params: valid_params
      expect(response).to redirect_to(post_path(Post.last))
    end

    it "returns unprocessable entity with invalid params" do
      post posts_path, params: { post: { title: "" } }
      expect(response).to have_http_status(:unprocessable_entity)
    end
  end

  describe "PATCH /posts/:id" do
    it "updates the post" do
      patch post_path(post), params: { post: { title: "Updated" } }
      expect(post.reload.title).to eq("Updated")
    end
  end

  describe "DELETE /posts/:id" do
    it "deletes the post" do
      post  # Create before counting
      expect {
        delete post_path(post)
      }.to change(Post, :count).by(-1)
    end

    it "redirects to index" do
      delete post_path(post)
      expect(response).to redirect_to(posts_path)
    end
  end
end
```

## System Specs (Browser Tests)

Test full user flows with a real browser. Located at `spec/system/posts_spec.rb`.

```ruby
# spec/system/posts_spec.rb
RSpec.describe "Posts", type: :system do
  let(:user) { create(:user) }

  before do
    driven_by(:selenium_headless)  # Or :selenium to see the browser
  end

  it "creates a new post" do
    visit new_post_path

    fill_in "Title", with: "My First Post"
    fill_in "Body", with: "This is the body content."
    select user.name, from: "User"
    click_button "Create Post"

    expect(page).to have_text("Post was successfully created")
    expect(page).to have_text("My First Post")
  end

  it "shows validation errors" do
    visit new_post_path
    click_button "Create Post"

    expect(page).to have_text("Title can't be blank")
  end
end
```

Run with: `rails spec` or `bundle exec rspec`.

## Mocks and Stubs

RSpec includes `allow` and `expect` for isolating tests from external dependencies.

### Stubs (Replace a Method)

```ruby
# Instead of hitting a real API
allow(WeatherService).to receive(:forecast).and_return("sunny")

# Now WeatherService.forecast returns "sunny" without making HTTP calls
```

### Mocks (Expect a Method to Be Called)

```ruby
# Verify a method was called with specific arguments
expect(Notifier).to receive(:send_email).with(user).once

# Trigger the action
PostsController.create
```

### Real Example: Mailer Mock

```ruby
RSpec.describe "POST /posts", type: :request do
  let(:user) { create(:user) }

  it "sends a notification email" do
    expect(PostMailer).to receive(:new_post).with(kind_of(Post)).and_call_original

    post posts_path, params: { post: attributes_for(:post, user_id: user.id) }
  end
end
```

### Real Example: External Service Stub

```ruby
RSpec.describe Post, type: :model do
  describe "#publish!" do
    let(:post) { create(:post, published: false) }

    before do
      # Stub the external service so we do not depend on it in tests
      allow(ImageUploader).to receive(:process).and_return(true)
    end

    it "marks the post as published" do
      post.publish!
      expect(post).to be_published
    end
  end
end
```

### let vs let!

|                          | `let`                           | `let!`                                         |
| ------------------------ | ------------------------------- | ---------------------------------------------- |
| When it runs             | Lazily — only when first called | Eagerly — runs before every test               |
| Use case                 | Read or query data              | Creating records needed even if not referenced |
| Example                  | `let(:user) { create(:user) }`  | `let!(:post) { create(:post) }`                |

## Best Practices

### File Structure

```
spec/
├── models/          # Unit tests for models
├── requests/        # Integration tests for controllers
├── system/          # Full browser tests
├── factories/       # Test data definitions
├── support/         # Custom helpers and shared contexts
├── spec_helper.rb
└── rails_helper.rb
```

Naming convention: `spec/<type>/<model_name>_spec.rb` matches the Rails model name.

### Rules

1. **One expectation per test** (or a few tightly related ones)
2. **Use Factory Bot**, never `Post.create(...)` inline — keeps tests maintainable
3. **Prefer request specs** over controller specs — they exercise the full stack (routing, params, response)
4. **Use system specs** sparingly — slow. Cover critical user flows only.
5. **Stub external services** — never hit real APIs in tests
6. **Keep factories minimal** — only include attributes needed for validation
7. **Run the whole suite often**: `bundle exec rspec`

### Running Tests

```bash
# All tests
bundle exec rspec

# Specific file
bundle exec rspec spec/models/post_spec.rb

# Specific line (test)
bundle exec rspec spec/models/post_spec.rb:5

# Tagged tests
bundle exec rspec --tag focus
```

## .NET Comparison

| Concept | NUnit / xUnit (.NET) | RSpec (Ruby) |
|---|---|---|
| **Test class** | `[TestFixture] public class PostTest` | `RSpec.describe Post, type: :model do` |
| **Test method** | `[Fact] public void Is_Valid()` | `it "is valid" do` |
| **Assertion** | `Assert.Equal(4, result)` | `expect(result).to eq(4)` |
| **Collection assert** | `Assert.Contains(post, posts)` | `expect(posts).to include(post)` |
| **Exception assert** | `Assert.Throws<Error>(() => ...)` | `expect { ... }.to raise_error(Error)` |
| **Mocking library** | Moq, NSubstitute | Built into RSpec (`allow`, `expect`) |
| **Test data** | AutoFixture, Bogus | Factory Bot, Faker |
| **Setup** | Constructor / `[SetUp]` | `before { ... }` / `let(:var) { ... }` |
| **Teardown**| `[TearDown]` | `after { ... }` |
| **Shared setup**| Base class with shared logic | `shared_context` / `shared_examples` |
| **Test runner**| `dotnet test` | `bundle exec rspec` |
| **Browser tests** | Selenium, Playwright (manual setup) | Capybara + Selenium (built-in system specs) |
| **Test DB** | In-memory / local DB | Test database (`RAILS_ENV=test`) |
| **Naming convention** | `PostTests.cs` → `PostTest` class | `spec/models/post_spec.rb` → `Post` describe |

### Same Test: Both Frameworks

**NUnit:**
```csharp
[TestFixture]
public class PostTest
{
    private TestDbContext _db;

    [SetUp]
    public void Setup()
    {
        _db = new TestDbContext();
    }

    [Test]
    public void Post_Is_Invalid_Without_Title()
    {
        var post = new Post { Body = "Content" };
        var errors = _db.Entry(post).GetValidationResult();

        Assert.Contains("Title", errors.Select(e => e.MemberName));
    }
}
```

**RSpec:**
```ruby
RSpec.describe Post, type: :model do
  it "is invalid without a title" do
    post = build(:post, title: nil)
    expect(post).not_to be_valid
    expect(post.errors[:title]).to include("can't be blank")
  end
end
```
