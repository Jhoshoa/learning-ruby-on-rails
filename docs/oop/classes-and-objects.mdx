# Classes and Objects

Ruby is a **pure object-oriented language**. Everything you interact with is an
object — numbers, strings, arrays, even classes themselves. Objects are
instances of classes.

## Defining a Class

Use the `class` keyword followed by the name in `PascalCase`.

```ruby
class Dog
end

fido = Dog.new    # Creating an instance
```

## The `initialize` Method (Constructor)

The `initialize` method is Ruby's **constructor**. It runs automatically every
time you call `.new`. If you're coming from another language:

| Language | Constructor |
|----------|-------------|
| Ruby | `def initialize` |
| JavaScript | `constructor()` |
| Python | `def __init__` |
| Java/C# | `ClassName()` |

```ruby
class Dog
  def initialize(name, breed)
    @name = name    # @name is an instance variable
    @breed = breed
    puts "#{@name} was just born!"
  end
end

fido = Dog.new("Fido", "Golden Retriever")
# => "Fido was just born!"
```

## Instance Variables (`@`)

Instance variables begin with `@` and belong to a specific object. Each instance
has its own copy.

```ruby
class Dog
  def initialize(name)
    @name = name
  end

  def speak
    "#{@name} says Woof!"
  end
end

fido = Dog.new("Fido")
bella = Dog.new("Bella")

fido.speak  # => "Fido says Woof!"
bella.speak # => "Bella says Woof!"
```

Instance variables are **private by default** — there is no way to access `@name`
from outside the class unless you define a getter method. Unlike some languages,
Ruby instance variables are always encapsulated and never part of a public
interface unless you explicitly expose them.

## Accessors (Getters and Setters)

Ruby provides shortcuts for creating getter and setter methods instead of
writing them manually:

```ruby
class Person
  # Manual getter
  def name
    @name
  end

  # Manual setter
  def name=(value)
    @name = value
  end
end
```

Instead, use these built-in **methods** (they are **not keywords** — they are
Module class methods that dynamically generate getter/setter methods for you at
runtime). The symbol you pass can be **any word** — the method name
(`_reader`/`_writer`/`_accessor`) determines what gets generated, not the
symbol itself:

```ruby
class Person
  attr_reader :name       # generates: def name;  @name; end
  attr_writer :age        # generates: def age=(val);  @age = val; end
  attr_accessor :email    # generates BOTH of the above patterns for @email
end
```

Same symbol `:name` behaves differently depending on which method you pass it
to:

| Call | Generates |
|------|-----------|
| `attr_reader :name` | `def name` → reads `@name` |
| `attr_writer :name` | `def name=(val)` → writes `@name` |
| `attr_accessor :name` | Both of the above |

The `_reader`, `_writer`, and `_accessor` suffixes are just naming conventions
for three separate methods — they are not part of the symbol itself.

```ruby
class Person
  attr_reader :name, :age     # generates reader for both
  attr_writer :age            # generates writer for age only
  attr_accessor :email        # generates both reader and writer for email
end
```

Because they are methods, you can even call them dynamically:

```ruby
class Person
  [:name, :age, :email].each { |attr| attr_accessor attr }
end
```

## Instance Methods vs Class Methods

**Instance methods** belong to objects (instances). They operate on the
object's state (instance variables). You call them on an instance.

**Class methods** belong to the class itself. They don't need an instance and
can't access instance variables. You call them directly on the class.

```ruby
class Dog
  # Instance method — called on an instance
  def bark
    "Woof!"
  end

  # Class method — called on the class itself
  def self.species
    "Canis familiaris"
  end

  # Another way to define a class method
  class << self
    def description
      "Dogs are domesticated mammals"
    end
  end
end

fido = Dog.new
fido.bark           # => "Woof!"
Dog.species         # => "Canis familiaris"
Dog.description     # => "Dogs are domesticated mammals"
Dog.bark            # => NoMethodError (class doesn't have instance methods)
fido.species        # => NoMethodError (instance doesn't have class methods)
```

### When to use each

| | Instance Method | Class Method |
|--|----------------|--------------|
| Needs a specific object? | Yes | No |
| Can access `@instance_vars`? | Yes | No |
| Example | `user.full_name` | `User.count` |
| Typical use | Object behavior | Utility, lookup, factory |

## Class Variables (`@@`)

Class variables are prefixed with `@@` and are **shared across all instances**
of the class and its subclasses.

```ruby
class Dog
  @@count = 0

  def initialize
    @@count += 1
  end

  def self.total
    @@count
  end
end

Dog.new
Dog.new
Dog.new
Dog.total  # => 3
```

:::caution
Class variables are shared with **all subclasses**, which can lead to
unexpected behaviour. Prefer **class instance variables** (`@var` at the class
level) when you want a variable that belongs only to the specific class, not
its descendants.
:::

### Class Instance Variables

A `@` variable defined **inside the class body but outside any method** belongs
to the class object itself (not instances). Each subclass gets its own copy:

```ruby
class Vehicle
  @count = 0

  def self.count
    @count || 0
  end

  def self.increment_count
    @count = (@count || 0) + 1
  end
end

class Car < Vehicle
  @count = 0
end

Vehicle.increment_count  # Vehicle.@count => 1
Car.count                # => 0 (separate from Vehicle)

# Compare with @@class variable:
class Vehicle
  @@count = 0

  def self.count
    @@count
  end
end

class Car < Vehicle; end

Vehicle.count  # => 0
Car.count      # => 0 (same @@count, shared!)
```

## Constants

Constants start with a capital letter. By convention, they are written in
`SCREAMING_SNAKE_CASE` for values and `PascalCase` for classes/modules.

```ruby
class Planet
  GRAVITY = 9.81      # constant
  MIN_NAME_LENGTH = 2

  def initialize(name)
    @name = name
  end
end

Planet::GRAVITY  # => 9.81
```

Constants can be accessed from outside the class with `::`. The lookup path is
**lexical** (based on where the code is written), not inheritance-based:

```ruby
class Animal
  LEGS = 4
end

class Dog < Animal
  def legs
    LEGS           # resolves to Animal::LEGS
  end
end

Dog.new.legs  # => 4
```

However, if a constant is not found lexically, Ruby walks up the inheritance
chain:

```ruby
class Animal
  SOUND = "generic"
end

class Dog < Animal
  SOUND = "bark"

  def sound
    SOUND  # finds Dog::SOUND first
  end
end

Dog.new.sound  # => "bark"
```

Constants are **not truly constant** — Ruby warns but doesn't prevent
reassignment:

```ruby
Planet::GRAVITY = 9.8   # warning: already initialized constant
```

## The `self` Keyword

`self` is a special variable that always points to the **current object** — the
receiver of the current method call. What it refers to changes based on where
you are:

| Location | `self` refers to |
|----------|-----------------|
| Inside an instance method | The instance (object) |
| Inside a class method | The class itself |
| Inside the class body (outside any method) | The class itself |
| At the top level (outside any class) | `main` (a special object) |

```ruby
puts self  # => main (top-level context)

class Dog
  puts self  # => Dog (class body)

  def bark
    self  # => the Dog instance (fido, bella, etc.)
  end

  def self.species
    self  # => Dog (the class)
  end
end
```

### Why use `self`?

Explicit `self` is needed when Ruby would otherwise think you're creating a
local variable:

```ruby
class Person
  attr_accessor :name

  def introduce
    # Without self: Ruby creates a local variable `name`
    name = "Local #{name}"

    # With self: calls the method `name=` (setter)
    self.name = "Overwritten"
  end
end
```

Setter methods (`name=`) **always** require `self` because otherwise Ruby sees
`name = value` as a local variable assignment:

```ruby
class Person
  attr_accessor :name

  def change_name(new_name)
    name = new_name   # local variable, NOT calling the setter
    self.name = new_name  # calls the setter
  end
end
```

For regular (non-setter) methods, `self` is optional — Ruby assumes the
current object:

```ruby
class Person
  def name
    @name
  end

  def formal_name
    "Mr. #{name}"    # self.name is implied — Ruby calls the method
    "Mr. #{self.name}"  # same thing, explicit
  end
end
```

## Converting to String (`to_s` and `inspect`)

Every class in Ruby automatically has a `to_s` method inherited from `Object`.
By default it returns the class name and object ID:

```ruby
class Dog; end

fido = Dog.new
puts fido  # => "#<Dog:0x00007f8b1a8b3d48>"
```

You can **override** it to provide a meaningful representation:

```ruby
class Dog
  def initialize(name)
    @name = name
  end

  def to_s
    "Dog: #{@name}"
  end
end

fido = Dog.new("Fido")
puts fido  # => "Dog: Fido"  (your custom to_s)

# to_s is called automatically in string interpolation too:
"A dog named #{fido}"  # => "A dog named Dog: Fido"
```

### `inspect` vs `to_s`

`inspect` is for **developers** (debugging) and `to_s` is for **users**
(display). The `p` method calls `inspect`; `puts` calls `to_s`.

```ruby
class Person
  def initialize(name, age)
    @name = name
    @age = age
  end

  def to_s
    "#{@name} (#{@age})"
  end

  def inspect
    "#<Person:#{object_id} @name=#{@name.inspect} @age=#{@age}>"
  end
end

alice = Person.new("Alice", 30)

puts alice  # => Alice (30)         (to_s)
p alice     # => #<Person:0x... @name="Alice" @age=30>  (inspect)
```

If you only override one, override `to_s`. `inspect` falls back to its default
(which shows the class and object ID). Override `inspect` when the default is
not helpful for debugging.

## Comparing Objects

Ruby provides three levels of comparison. Understanding the difference is
critical:

| Method | Compares | Default behavior | When to override |
|--------|----------|-----------------|-----------------|
| `==` | **Value** (equality) | Checks if same object (`equal?`) | Most common — compare by attributes |
| `eql?` | **Value + Type** (hash equality) | Same as `==` | Used by Hashes for key matching |
| `equal?` | **Identity** (same object) | Checks object_id | Never override |
| `===` | **Case equality** | Same as `==` | Used by `case/when` |

```ruby
class Dog
  attr_reader :name, :breed

  def initialize(name, breed)
    @name = name
    @breed = breed
  end

  # Value equality — are these dogs the same?
  def ==(other)
    return false unless other.is_a?(Dog)
    name == other.name && breed == other.breed
  end

  alias eql? ==  # make eql? behave the same as ==
end

fido1 = Dog.new("Fido", "Golden")
fido2 = Dog.new("Fido", "Golden")
fido3 = fido1

fido1 == fido2   # => true  (same values — our custom ==)
fido1 == fido3   # => true  (same values AND same object)
fido1.equal?(fido2)  # => false  (different objects in memory)
fido1.equal?(fido3)  # => true  (same object)
```

Without a custom `==`, Ruby falls back to `equal?` behavior, so two objects
with identical attributes would be considered "not equal":

```ruby
class Dog
  def initialize(name)
    @name = name
  end
  # no custom == defined
end

Dog.new("Fido") == Dog.new("Fido")  # => false (default: same object?)
```

### The `===` (Case Equality) Operator

`===` is used by `case`/`when` statements. Each class defines it differently:

```ruby
case value
when String  then "It's a string"     # String === value
when 1..10   then "Between 1 and 10"  # Range === value
when /hello/ then "Contains hello"    # Regexp === value
else "Something else"
end

# Equivalent to:
if String === value
  "It's a string"
elsif (1..10) === value
  "Between 1 and 10"
elsif /hello/ === value
  "Contains hello"
end
```

| Class | `===` behavior |
|-------|----------------|
| `Class` | `is_a?` — checks if the value is an instance of that class |
| `Range` | `include?` — checks if the value falls in the range |
| `Regexp` | `match?` — checks if the string matches |
| `Proc` | `call` — invokes the proc with the value |
| Default | Same as `==` |

## Copying Objects: `dup` vs `clone`

```ruby
original = "hello"
original.freeze

dup_obj   = original.dup    # unfrozen copy
clone_obj = original.clone  # frozen copy (preserves state)
```

| Behaviour | `dup` | `clone` |
|-----------|-------|---------|
| Copies instance variables | Yes | Yes |
| Preserves frozen state | No | Yes |
| Preserves singleton methods | No | Yes |
| Preserves tainted state | Yes | Yes |

Both `dup` and `clone` perform **shallow copies** — instance variables that
reference objects still reference the same objects:

```ruby
class Team
  attr_accessor :members

  def initialize
    @members = []
  end
end

team1 = Team.new
team1.members << "Alice"

team2 = team1.dup
team2.members << "Bob"

team1.members  # => ["Alice", "Bob"]  — same array object!
```

To deep-copy, override `initialize_copy`:

```ruby
class Team
  def initialize_copy(original)
    super            # copies instance variables first
    @members = @members.dup  # create a new array
  end
end
```

## Freezing Objects

`freeze` makes an object immutable — you cannot modify its state:

```ruby
str = "hello".freeze
str.upcase!  # FrozenError: can't modify frozen String

str.upcase   # => "HELLO"  (returns new string, OK — doesn't modify)
```

Check if something is frozen with `frozen?`:

```ruby
"hello".frozen?      # => false
"hello".freeze.frozen?  # => true
```

## The `tap` Method

`tap` yields the object to a block and returns the object itself. It is perfect
for debugging or chaining mutations:

```ruby
result = [1, 2, 3]
  .map { |n| n * 2 }
  .tap { |arr| puts "After map: #{arr}" }  # => [2, 4, 6]
  .reject(&:even?)
  .tap { |arr| puts "After reject: #{arr}" }  # => []

# Common pattern: initializing and returning an object
def build_user(params)
  User.new.tap do |user|
    user.name = params[:name]
    user.email = params[:email]
    user.save!
  end
end
# The tap block runs, then user is returned automatically
```

## Dynamic Method Calling: `send` and `public_send`

`send` lets you call a method by name (as a Symbol or String):

```ruby
obj = "hello"

obj.send(:upcase)   # => "HELLO"
obj.send(:reverse)  # => "olleh"
```

`public_send` is like `send` but respects method visibility (won't call private
methods):

```ruby
obj.public_send(:upcase)           # => "HELLO"
obj.send(:nil?)                     # => false (nil? is public)
obj.send(:puts, "hello")            # => nil (private method, but send bypasses)
obj.public_send(:puts, "hello")     # NoMethodError (private)
```

Always check with `respond_to?` before dynamically calling:

```ruby
obj.respond_to?(:upcase)  # => true
```

## Getting Method Objects

You can get a method as an object and pass it around:

```ruby
m = "hello".method(:upcase)
m.call    # => "HELLO"
m.arity   # => 0
m.owner   # => String

# Pass as callback
["a", "b", "c"].map(&:upcase)  # Symbol#to_proc
```

## Public and Private Methods

Ruby has three access modifiers, but they work differently than in languages
like C# or Java:

| Modifier | C# / Java | Ruby |
|----------|-----------|------|
| `public` | Default. Anyone can call it. | Default. Anyone can call it. |
| `private` | Only the class itself. | Only the class itself — **but with a catch** (see below). |
| `protected` | Only the class and subclasses. | Same as `private`, but allows access between same-class instances. |
| `internal` | Only within the same assembly. | **Does not exist** in Ruby. |

### Private

By default all methods are `public`. Use `private` to hide internal details.
Once `private` is declared, all subsequent methods are private.

```ruby
class BankAccount
  def initialize(balance)
    @balance = balance
  end

  def withdraw(amount)
    if sufficient_funds?(amount)
      @balance -= amount
    else
      "Insufficient funds"
    end
  end

  private  # everything below is private

  def sufficient_funds?(amount)
    @balance >= amount
  end
end

account = BankAccount.new(100)
account.withdraw(30)           # => 70
account.sufficient_funds?(50)  # => NoMethodError (private method)
```

### The private gotcha

In Ruby, `private` means the method can only be called **without** a receiver
— you cannot call `self.method_name`. This is different from C#/Java where
`self.method_name` works fine:

```ruby
class BankAccount
  private

  def secret
    "hidden"
  end

  def try_to_call
    secret          # => "hidden" (OK)
    self.secret     # => NoMethodError (private — can't use self.)
  end
end
```

Private methods **can** be called by subclasses (unlike C# where private is
truly private to the class):

```ruby
class SavingsAccount < BankAccount
  def check
    secret  # => "hidden"  (works! Private doesn't prevent subclass access)
  end
end
```

### Protected

`protected` works like `private` (callable without a receiver), but **allows
calling the method on another instance of the same class**:

```ruby
class Person
  attr_reader :age

  def initialize(name, age)
    @name = name
    @age = age
  end

  def older_than?(other)
    age > other.age  # calling protected method on another instance
  end

  protected

  def age
    @age
  end
end

alice = Person.new("Alice", 30)
bob = Person.new("Bob", 25)

alice.older_than?(bob)  # => true  (protected allows same-class access)
alice.age                # => NoMethodError (protected — no external access)
```

### Marking individual methods inline

Instead of a block modifier, you can mark specific methods inline:

```ruby
class BankAccount
  def withdraw(amount)
    sufficient_funds?(amount)
  end

  private def sufficient_funds?(amount)
    @balance >= amount
  end
end
```

## The `allocate` Method

Normally you create objects with `new`, which calls `allocate` then
`initialize`. If you need an object **without** calling `initialize`, use
`allocate` directly:

```ruby
class User
  def initialize(name)
    @name = name
    @setup = true
  end
end

user = User.allocate
user.instance_variables  # => []  (initialize was never called)
user.instance_variable_set(:@name, "Alice")
user.instance_variable_get(:@name)  # => "Alice"
```

This is an advanced technique used internally by ORMs (ActiveRecord, etc.)
to reconstruct objects from the database without calling their constructors.

## Type Checking

```ruby
class Animal; end
class Dog < Animal; end

fido = Dog.new

fido.instance_of?(Dog)      # => true (exact class match)
fido.instance_of?(Animal)   # => false (exact class, no inheritance)

fido.is_a?(Dog)             # => true
fido.is_a?(Animal)          # => true (checks inheritance chain)
fido.is_a?(Object)          # => true (everything is an Object)
fido.kind_of?(Animal)       # => true (alias for is_a?)
```

## The Singleton Class (Eigenclass)

Every object in Ruby has an invisible **singleton class** (also called
eigenclass) that stores methods unique to that object. This is how class
methods and per-object behaviour work.

```ruby
obj = "hello"

# Open the singleton class
class << obj
  def shout
    upcase + "!"
  end
end

obj.shout  # => "HELLO!"
"world".shout  # NoMethodError — only obj has it

# Access the singleton class object
singleton_class = class << obj; self; end
obj.singleton_class  # same thing
```

Class methods are just singleton methods on the class object:

```ruby
class MyClass
  class << self
    def class_method
      "I'm a class method"
    end
  end
end

# Equivalent to:
def MyClass.class_method
  "I'm a class method"
end
```

## The `nil?` Method

The only object for which `nil?` returns `true` is `nil` itself:

```ruby
nil.nil?      # => true
false.nil?    # => false
0.nil?        # => false
"".nil?       # => false
```

This is useful for safe default patterns:

```ruby
def find_user(id)
  # ...
end

user = find_user(42)
user.nil? ? "Guest" : user.name
```
