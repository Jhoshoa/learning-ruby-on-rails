Classes and Objects

Ruby is a pure object-oriented language. Everything you interact with is an object—numbers, strings, arrays, even classes themselves. Objects are instances of classes.

Defining a Class​

Use the class keyword followed by the name in PascalCase.

class Dog
end

fido = Dog.new    # Creating an instance

The initialize Method (Constructor)​

The initialize method is Ruby's constructor. It runs automatically every time you call .new. If you're coming from another language:

LanguageConstructor
Rubydef initialize
JavaScriptconstructor()
Pythondef __init__
Java/C#ClassName()
class Dog
  def initialize(name, breed)
    @name = name    # @name is an instance variable
    @breed = breed
    puts "#{@name} was just born!"
  end
end

fido = Dog.new("Fido", "Golden Retriever")
# => "Fido was just born!"

Instance Variables (@)​

Instance variables begin with @ and belong to a specific object. Each instance has its own copy.

class Dog
  def initialize(name)
    @name = name
  end

  def speak
    "#{@name} says Woof!"
  end
end

fido = Dog.new("Fido")
bella = Dog.new("Bella")

fido.speak  # => "Fido says Woof!"
bella.speak # => "Bella says Woof!"

Accessors (Getters and Setters)​

Ruby provides shortcuts for creating getter and setter methods instead of writing them manually:

class Person
  # Manual getter
  def name
    @name
  end

  # Manual setter
  def name=(value)
    @name = value
  end
end

Instead, use these built-in methods (they are not keywords — they are class methods that dynamically generate getter/setter methods for you at runtime). The symbol you pass can be any word — the method name (_reader/_writer/_accessor) determines what gets generated, not the symbol itself:

class Person
  attr_reader :name       # generates: def name;  @name; end
  attr_writer :age        # generates: def age=(val);  @age = val; end
  attr_accessor :email    # generates BOTH of the above patterns for @email
end

Same symbol :name behaves differently depending on which method you pass it to:

CallGenerates
attr_reader :namedef name → reads @name
attr_writer :namedef name=(val) → writes @name
attr_accessor :nameBoth of the above

The _reader, _writer, and _accessor suffixes are just naming conventions for three separate methods — they are not part of the symbol itself.

class Person
  attr_reader :name, :age     # generates reader for both
  attr_writer :age            # generates writer for age only
  attr_accessor :email        # generates both reader and writer for email
end

Because they are methods, you can even call them dynamically:

class Person
  [:name, :age, :email].each { |attr| attr_accessor attr }
end

Instance Methods vs Class Methods​

Instance methods belong to objects (instances). They operate on the object's state (instance variables). You call them on an instance.

Class methods belong to the class itself. They don't need an instance and can't access instance variables. You call them directly on the class.

class Dog
  # Instance method — called on an instance
  def bark
    "Woof!"
  end

  # Class method — called on the class itself
  def self.species
    "Canis familiaris"
  end

  # Another way to define a class method
  class << self
    def description
      "Dogs are domesticated mammals"
    end
  end
end

fido = Dog.new
fido.bark           # => "Woof!"
Dog.species         # => "Canis familiaris"
Dog.description     # => "Dogs are domesticated mammals"
Dog.bark            # => NoMethodError (class doesn't have instance methods)
fido.species        # => NoMethodError (instance doesn't have class methods)

Can access @instance_vars?YesNo

Class Variables (@@)​

Class variables are prefixed with @@ and are shared across all instances of the class and its subclasses.

class Dog
  @@count = 0

  def initialize
    @@count += 1
  end

  def self.total
    @@count
  end
end

Dog.new
Dog.new
Dog.new
Dog.total  # => 3

The self Keyword​

self is a special variable that always points to the current object — the receiver of the current method call. What it refers to changes based on where you are:

Locationself refers to
Inside an instance methodThe instance (object)
Inside a class methodThe class itself
Inside the class body (outside any method)The class itself
At the top level (outside any class)main (a special object)
puts self  # => main (top-level context)

class Dog
  puts self  # => Dog (class body)

  def bark
    self  # => the Dog instance (fido, bella, etc.)
  end

  def self.species
    self  # => Dog (the class)
  end
end

Why use self?​

Explicit self is needed when Ruby would otherwise think you're creating a local variable:

class Person
  attr_accessor :name

  def introduce
    # Without self: Ruby creates a local variable `name`
    name = "Local #{name}"

    # With self: calls the method `name=` (setter)
    self.name = "Overwritten"
  end
end

Setter methods (name=) always require self because otherwise Ruby sees name = value as a local variable assignment:

class Person
  attr_accessor :name

  def change_name(new_name)
    name = new_name   # local variable, NOT calling the setter
    self.name = new_name  # calls the setter
  end
end

For regular (non-setter) methods, self is optional — Ruby assumes the current object:

class Person
  def name
    @name
  end

  def formal_name
    "Mr. #{name}"    # self.name is implied — Ruby calls the method
    "Mr. #{self.name}"  # same thing, explicit
  end
end

Converting to String (to_s)​

Every class in Ruby automatically has a to_s method inherited from Object. By default it returns the class name and object ID:

class Dog; end

fido = Dog.new
puts fido  # => "#<Dog:0x00007f8b1a8b3d48>"

You can override it to provide a meaningful representation:

class Dog
  def initialize(name)
    @name = name
  end

  def to_s
    "Dog: #{@name}"
  end
end

fido = Dog.new("Fido")
puts fido  # => "Dog: Fido"  (your custom to_s)

# to_s is called automatically in string interpolation too:
"A dog named #{fido}"  # => "A dog named Dog: Fido"

Comparing Objects​

Ruby provides three levels of comparison. Understanding the difference is critical:

MethodComparesDefault behaviorWhen to override
==Value (equality)Checks if same object (equal?)Most common — compare by attributes
eql?Value + Type (hash equality)Same as ==Used by Hashes for key matching
equal?Identity (same object)Checks object_idNever override
===Case equalitySame as ==Used by case/when
class Dog
  attr_reader :name, :breed

  def initialize(name, breed)
    @name = name
    @breed = breed
  end

  # Value equality — are these dogs the same?
  def ==(other)
    return false unless other.is_a?(Dog)
    name == other.name && breed == other.breed
  end

  alias eql? ==  # make eql? behave the same as ==
end

fido1 = Dog.new("Fido", "Golden")
fido2 = Dog.new("Fido", "Golden")
fido3 = fido1

fido1 == fido2   # => true  (same values — our custom ==)
fido1 == fido3   # => true  (same values AND same object)
fido1.equal?(fido2)  # => false  (different objects in memory)
fido1.equal?(fido3)  # => true  (same object)

Without a custom ==, Ruby falls back to equal? behavior, so two objects with identical attributes would be considered "not equal":

class Dog
  def initialize(name)
    @name = name
  end
  # no custom == defined
end

Dog.new("Fido") == Dog.new("Fido")  # => false (default: same object?)

Public and Private Methods​

Ruby has three access modifiers, but they work differently than in languages like C# or Java:

ModifierC# / JavaRuby
publicDefault. Anyone can call it.Default. Anyone can call it.
privateOnly the class itself.Only the class itself — but with a catch (see below).
protectedOnly the class and subclasses.Same as private, but allows access between same-class instances.
internalOnly within the same assembly.Does not exist in Ruby.

Private​

By default all methods are public. Use private to hide internal details. Once private is declared, all subsequent methods are private.

class BankAccount
  def initialize(balance)
    @balance = balance
  end

  def withdraw(amount)
    if sufficient_funds?(amount)
      @balance -= amount
    else
      "Insufficient funds"
    end
  end

  private  # everything below is private

  def sufficient_funds?(amount)
    @balance >= amount
  end
end

account = BankAccount.new(100)
account.withdraw(30)           # => 70
account.sufficient_funds?(50)  # => NoMethodError (private method)

The private gotcha​

In Ruby, private means the method can only be called without a receiver — you cannot call self.method_name. This is different from C#/Java where self.method_name works fine:

class BankAccount
  private

  def secret
    "hidden"
  end

  def try_to_call
    secret          # => "hidden" (OK)
    self.secret     # => NoMethodError (private — can't use self.)
  end
end

Private methods can be called by subclasses (unlike C# where private is truly private to the class):

class SavingsAccount < BankAccount
  def check
    secret  # => "hidden"  (works! Private doesn't prevent subclass access)
  end
end

Protected​

protected works like private (callable without a receiver), but allows calling the method on another instance of the same class:

class Person
  attr_reader :age

  def initialize(name, age)
    @name = name
    @age = age
  end

  def older_than?(other)
    age > other.age  # calling protected method on another instance
  end

  protected

  def age
    @age
  end
end

alice = Person.new("Alice", 30)
bob = Person.new("Bob", 25)

alice.older_than?(bob)  # => true  (protected allows same-class access)
alice.age                # => NoMethodError (protected — no external access)

Marking individual methods inline​

Instead of a block modifier, you can mark specific methods inline:

class BankAccount
  def withdraw(amount)
    sufficient_funds?(amount)
  end

  private def sufficient_funds?(amount)
    @balance >= amount
  end
end
