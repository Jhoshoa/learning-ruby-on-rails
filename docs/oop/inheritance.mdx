# Inheritance

Ruby supports **single inheritance** — a class can inherit from only one parent
class. The symbol `<` denotes inheritance.

## Basic Inheritance

The child class gets all the methods of the parent class and can override them.

```ruby
class Animal
  def speak
    "Some sound"
  end

  def eat
    "Eating..."
  end
end

class Dog < Animal
  def speak    # override
    "Woof!"
  end
end

class Cat < Animal
  def speak    # override
    "Meow!"
  end
end

Dog.new.speak  # => "Woof!"
Cat.new.speak  # => "Meow!"
Cat.new.eat    # => "Eating..."  (inherited from Animal)
```

## The `super` Keyword

`super` calls the parent class's **same-named method**. It has three behaviors:

| `super` call | What it does |
|-------------|--------------|
| `super` | Calls parent method with **all** original arguments |
| `super()` | Calls parent method with **no** arguments |
| `super(a, b)` | Calls parent method with **specific** arguments |

```ruby
class Animal
  def initialize(name)
    @name = name
  end
end

class Dog < Animal
  def initialize(name, breed)
    super(name)  # passes name to Animal's initialize
    @breed = breed
  end
end

Dog.new("Fido", "Golden Retriever")
```

Another example with method override:

```ruby
class Animal
  def move
    "Moves somehow"
  end
end

class Bird < Animal
  def move
    super + " by flying"   # calls Animal#move and adds to it
  end
end

class Fish < Animal
  def move
    super + " by swimming"
  end
end

Bird.new.move  # => "Moves somehow by flying"
Fish.new.move  # => "Moves somehow by swimming"
```

### `super` with Blocks

`super` passes the block to the parent method automatically. You don't need to
explicitly forward it:

```ruby
class Parent
  def each
    yield "A"
    yield "B"
  end
end

class Child < Parent
  def each
    super do |item|
      yield "Child: #{item}"
    end
  end
end

Child.new.each { |s| puts s }
# => "Child: A"
# => "Child: B"
```

### `super` in Class Methods

`super` also works in class methods:

```ruby
class Parent
  def self.config
    { adapter: "sqlite3" }
  end
end

class Child < Parent
  def self.config
    super.merge(pool: 5)
  end
end

Child.config  # => { adapter: "sqlite3", pool: 5 }
```

## Overriding Methods

Child classes can completely replace parent methods or extend them with `super`.

```ruby
class Vehicle
  def start
    "Engine starting..."
  end
end

class Car < Vehicle
  def start
    "Insert key. " + super + " Vroom!"
  end
end

Car.new.start  # => "Insert key. Engine starting... Vroom!"
```

## `initialize` is Inherited

If a child class **doesn't** define `initialize`, the parent's `initialize` is
used:

```ruby
class Animal
  def initialize(name)
    @name = name
  end

  attr_reader :name
end

class Dog < Animal
  # No initialize defined — inherits Animal#initialize
end

fido = Dog.new("Fido")
fido.name  # => "Fido"
```

If the child **does** define `initialize`, it must call `super` to invoke the
parent's constructor, otherwise the parent's setup is skipped:

```ruby
class Animal
  def initialize(name)
    @name = name
  end
end

class Dog < Animal
  def initialize(name, breed)
    # Forgot to call super(name) — @name is never set
    @breed = breed
  end
end

Dog.new("Fido", "Golden").instance_variable_get(:@name)  # => nil
```

## Overriding `==` with Inheritance

When overriding `==` in a hierarchy, use `is_a?` (not `instance_of?`) to allow
subclass comparisons:

```ruby
class Animal
  attr_reader :name

  def initialize(name)
    @name = name
  end

  def ==(other)
    return false unless other.is_a?(Animal)
    name == other.name
  end
end

class Dog < Animal
  attr_reader :breed

  def initialize(name, breed)
    super(name)
    @breed = breed
  end

  def ==(other)
    return false unless other.is_a?(Dog)
    super && breed == other.breed
  end
end

animal = Animal.new("Fido")
dog = Dog.new("Fido", "Golden")

dog == animal   # => false (Dog#== checks is_a? Dog)
animal == dog   # => true  (Animal#== checks is_a? Animal)
```

## The Abstract Method Pattern

Ruby has no `abstract` keyword. Instead, raise `NotImplementedError` in the
parent method to force subclasses to override:

```ruby
class Animal
  def speak
    raise NotImplementedError,
      "#{self.class} must implement #speak"
  end
end

class Dog < Animal
  def speak
    "Woof!"
  end
end

class Cat < Animal
  # Forgot to implement speak
end

Dog.new.speak  # => "Woof!"
Cat.new.speak  # => NotImplementedError: Cat must implement #speak
```

## The `class` and `superclass` Methods

Every object in Ruby knows its class and every class knows its parent:

```ruby
fido = Dog.new("Fido")

fido.class               # => Dog
fido.class.superclass    # => Animal
Animal.superclass         # => Object
Object.superclass         # => BasicObject
BasicObject.superclass    # => nil

# Check inheritance relationship
Dog < Animal        # => true
Animal < Dog        # => false
Dog < Object        # => true
Dog < BasicObject   # => true
Dog < String        # => nil (not related)
```

## `dup` and `clone` in Inheritance

If you override `initialize_copy`, remember to call `super` to copy parent
instance variables:

```ruby
class Animal
  attr_accessor :name

  def initialize_copy(original)
    super
    # Animal-specific copy logic if needed
  end
end

class Dog < Animal
  attr_accessor :breed

  def initialize_copy(original)
    super
    @breed = @breed.dup  # deep-copy mutable attributes
  end
end
```

## Type Checking: `is_a?` vs `instance_of?`

```ruby
class Animal; end
class Dog < Animal; end

fido = Dog.new

fido.is_a?(Dog)      # => true
fido.is_a?(Animal)   # => true (because Dog inherits from Animal)
fido.is_a?(Object)   # => true (everything inherits from Object)

fido.instance_of?(Dog)     # => true
fido.instance_of?(Animal)  # => false (exact class, no inheritance)
```

- `is_a?` checks the entire inheritance chain
- `instance_of?` checks the exact class only

## Method Lookup Path

When Ruby looks for a method, it follows this order:

1. The object's own singleton class
2. The object's class
3. Prepended modules (last prepended searched first)
4. Included modules (last included searched first)
5. Parent class
6. Parent's prepended/included modules
7. Repeat up the chain to `BasicObject`

```ruby
class Animal; end
module Swimmable; end
module Climbable; end

class Dog < Animal
  include Swimmable
  include Climbable
end

Dog.ancestors
# => [Dog, Climbable, Swimmable, Animal, Object, Kernel, BasicObject]
```

Use `Dog.ancestors` to see the full lookup chain at any time. Use
`Dog.included_modules` to see just the mixed-in modules:

```ruby
Dog.included_modules  # => [Climbable, Swimmable, Kernel]
```

## Inheritance vs Modules (When to Use What)

| Use Inheritance (`<`) | Use Modules (`include`) |
|----------------------|------------------------|
| "Is-a" relationship (Dog is an Animal) | "Has-a" or "Can" relationship (Dog can swim) |
| Shared base behavior | Shared behavior across unrelated classes |
| One parent only | As many modules as you want |

```ruby
# Inheritance: Dog IS-AN Animal
class Dog < Animal
end

# Modules: Dog CAN swim, CAN fetch
module Swimmable; end
module Fetchable; end

class Dog < Animal
  include Swimmable
  include Fetchable
end
```

## `respond_to?` — Checking Before Calling

Always safe to check if an object can respond to a method:

```ruby
obj = "hello"
obj.respond_to?(:upcase)   # => true
obj.respond_to?(:fly)      # => false

obj.send(:upcase)          # => "HELLO" (calls method dynamically)
```
